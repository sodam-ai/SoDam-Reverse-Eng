### 1~2단계: 동의 확인 (번호 선택 — 자연어 "예/아니오" 타이핑 요구 금지)

`AskUserQuestion` 도구로 아래 2개 질문을 **한 번에** 물어보세요. 사용자가 "예"/"아니오"를 직접 타이핑하게 하지 말고, 반드시 선택지를 눌러 고르는 형태로 제시하세요:

- 질문 1 (header: "소유권") — "이 파일/코드는 본인이 직접 만들었거나, 분석 권한을 가진 것이 맞나요?"
  - 옵션: "예, 맞습니다" / "아니오"
- 질문 2 (header: "이용 동의") — "분석 결과를 방어·학습·본인 소유물 목적으로만 쓰고, 불법 활동(크랙·우회·키추출)에 쓰지 않겠다는 데 동의하나요?"
  - 옵션: "예, 동의합니다" / "아니오"

- **두 질문 모두 "예" 계열 선택** → 3단계 진행
- **하나라도 "아니오" 선택 또는 응답 거부** → 즉시 중단: "동의가 확인되지 않아 분석할 수 없습니다."

---

### 3단계: 분석 및 보고서 (1·2단계 모두 '예'인 경우만)

Read 도구로 대상 파일을 읽고 아래 형식으로 한국어 보고서를 작성하세요.

**보고서 형식:**

```
# SoDam-Reverse 분석 보고서

## 한 줄 요약
이 코드가 무엇을 하는지 한 줄로 — 초등학생도 이해하는 언어로

## 함수별 설명
- `함수명()` (파일명:줄번호) — 하는 일을 쉬운 말로

## 근거 위치
- 주장 → 파일명:줄번호  (※ 실제 코드와 일치해야 함 = 정확성 게이트)

## 불확실한 점
- 확신하지 못하는 부분 (추정과 "확인됨"을 분리해 표기)

## 다음 확인사항
- 사람이 직접 봐야 할 부분

## ⚠️ 안전
- 위험이 의심돼도 단정하지 않는다: "안전/위험 단정 불가 — 전문가 확인 필요"
- 분석 중 발견한 키/토큰/비밀번호는 ••••로 마스킹
```

**반드시 지킬 규칙:**
- 파일 실행 금지 (Read로 읽기만)
- API 키·비밀번호 발견 시 `••••` 마스킹
- 근거 위치(파일명:줄번호)가 실제 코드와 일치하는지 확인
- 전문용어는 괄호 안에 쉬운 설명 추가
