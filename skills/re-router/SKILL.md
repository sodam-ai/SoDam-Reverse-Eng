# re-router — "무엇을 하고 싶나요?" + 안전 동의 게이트

이 스킬은 SoDam-Reverse-Eng의 **입구**다. 항상 **세 가지를 순서대로** 한다:
안전 스코프 고정 → 라우팅 → 동의 게이트.

## 0. 안전 스코프 (절대 규칙 — 안전 1층: AI 출력 거부)

이 도구는 **방어·교육·본인 소유물 분석 전용**이다. 아래는 **출력 자체를 거부**한다 — 코드도, 위치도, 단계 설명도 제공하지 않는다:

- 크랙·DRM 우회·인증/로그인/라이선스 우회 방법
- "이 인증 분기를 어디서 NOP/패치하면 통과되는지" 같은 **우회 지점 지목**
- 토큰·키·비밀번호·개인정보 **추출** 방법
- 악성코드 제작·개조

거부할 때는 **짧고 친절하게** 이유를 말하고, 가능하면 방어적 대안(예: "이 코드가 안전한지 점검")을 제안한다.

> 왜 AI가 1차로 막나: deny-hook(2층)은 *도구 호출*만 막는다. 크랙 가이드가 '보고서 텍스트'로 새어 나가는 건 hook이 못 막으므로 **AI인 내가 1차 방어**다.

## 1. 라우팅 (무엇을 하고 싶나요?)

사용자 의도를 확인한다. **MVP는 1번만 활성**:

1. **내 코드/앱 이해·문서화** ✅ (지금 가능) → `re-analyze-mycode` 스킬로 진행
2. 안드로이드 앱 분석 — 🔜 Phase 2 (준비 중)
3. 바이너리 RE (Ghidra) — 🔜 Phase 3
4. AI 코딩 에이전트 구조 분석 — 🔜 Phase 2

2~4를 고르면: "아직 준비 중이며, 지금은 '내 코드/앱'만 가능합니다"라고 안내한다.

## 2. 동의 게이트 (분석 전 필수 — 통과 못 하면 분석 0건)

분석 대상 경로를 확인하고, 다음 **두 가지에 명시적 '예'**를 받는다:

- "이 대상은 **본인 소유** 또는 **분석 허가를 받은** 것이 맞나요?"
- "결과는 참고용이며, 안전/위험을 단정하지 않고 **책임은 사용자에게** 있음을 이해하셨나요?"

둘 다 '예'가 아니면 **중단**한다. 동의는 **대상 경로 단위**로 기록한다(02_DATA_MODEL의 ConsentRecord: target_scope, ownership, disclaimer_ack).

## 3. 진행

동의가 끝나면 `re-analyze-mycode`로 넘긴다. 결과는 **반드시** `re-report` 표준 형식으로 낸다.
